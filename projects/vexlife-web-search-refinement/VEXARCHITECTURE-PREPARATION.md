# VexArchitecture preparation — bounded public-web research

`[VXG RealForever]`

## Status / boundary

This is a **preparation map**, not implementation authority and not accepted capability naming.

It exists so Web Search Refinement consumes the same VexArchitecture relationships being stabilized by New Beginnings instead of building a parallel research framework.

```text
PREPARATION
!= PROVIDER SELECTION
!= NETWORK EFFECT AUTHORITY
!= NEW MEMORY OWNER
!= NEW SCHEDULER
!= NEW TOOL RELAY
```

Before implementation, re-open the current New Beginnings VexArchitecture source and the current Interface Refinement owners. Preserve current truth over this note if they differ.

## Human intention

```text
Victor asks something that requires current public information
        ↓
Vex recognizes current external evidence is needed
        ↓
Vex discovers an admitted public-read capability
        ↓
bounded search identifies candidate sources
        ↓
bounded fetch/read observes selected evidence
        ↓
external content remains untrusted data
        ↓
Vex relates claims to exact source/currentness evidence
        ↓
Vex answers naturally
        ↓
same canonical Conversation remains current
```

The product intention is **ordinary research**, not "use the Internet tool."

## Architectural questions to preserve

The preparation should pressure existing owners through these questions rather than preselecting class names.

### 1. Capability need

```text
Does this turn require current external information?
```

This belongs with current Conversation/task/capability awareness. It is not web-provider state.

### 2. Capability admission

```text
Given the current Capability/Atlas projection,
what public-read Control is actually lawful now?
```

Reuse the existing capability runtime / scheduler / leases. Do not create a WebSearch scheduler.

### 3. Provider-boundary context budget

```text
What exact provider-bound input is lawful
inside the one current Context Lease budget?
```

The accounting must include, as applicable:

```text
Conversation
Memory
Foundation / Atlas / self-capability frame
task
capability request/synthesis instructions
active tool observations
bounded research findings
```

Permanent:

```text
SUPPLEMENTAL BYTE CAP
!= FINAL PROVIDER TOKEN BUDGET

PER-OBSERVATION LIMIT
!= TURN-LEVEL OBSERVATION BUDGET
```

This is a cross-capability architecture pressure point, not a web-specific workaround.

### 4. Candidate-source discovery

```text
Which public sources are candidates for the current information need?
```

Likely realized by a search capability.

Search result metadata is candidate evidence, not truth.

### 5. Public-source admission

```text
Is this destination/public source lawful to observe?
```

The network-read effect must preserve public-only destination/currentness rules and must not inherit authority from page text.

### 6. Exact external observation

```text
What was actually observed from which source, when,
under which retrieval/currentness boundary?
```

Observation should remain source-addressed and structurally non-authoritative.

Conceptual truth class:

```text
UNTRUSTED_EXTERNAL_CONTENT
```

Exact naming remains to be earned.

### 7. Claim/evidence relationship

```text
Which bounded claim or finding is supported by which observations,
and where are contradiction / uncertainty boundaries?
```

This is not Memory promotion.

### 8. Observation lifetime

```text
Which raw observations still need active model context,
which may be evicted,
and which exact evidence may be rehydrated later?
```

The runtime/resource relationship owns finite-context reclamation.

The model may choose what evidence remains relevant. It should not have to remember a manual `clear()` ritual.

### 9. Conversation completion

```text
What source-grounded answer becomes durable
in the same canonical Conversation?
```

Tool observations are not Conversation messages by implication; synthesis enters Conversation through the existing turn owner.

## Fractal boundary

Do not turn every search result, HTTP redirect, parser helper or text chunk into a VexArchitecture stage.

Use the New Beginnings law:

```text
FRACTAL EXPANSION
= MEANINGFUL INTENTION / TRUTH BOUNDARY

FRACTAL EXPANSION
!= EVERY IMPLEMENTATION STEP
```

Examples that normally remain implementation detail:

```text
encode query parameters
parse JSON
normalize a URL
hash an observation body
split extracted text into bounded ranges
```

Examples that can earn semantic boundaries:

```text
candidate result
!= admitted public source

HTTP response
!= trusted instruction

raw observation present
!= observation still allocated in active context

finding exists
!= durable Memory

provider returned content
!= claim supported

public GitHub page readable
!= repository mutation authority
```

## Search and fetch

Preserve the distinct questions unless implementation proves they collapse without loss:

```text
SEARCH
"What candidate public sources may answer this question?"

FETCH / READ
"What bounded evidence does this selected source currently expose?"
```

Provider/vendor identity should remain below the semantic capability boundary.

Do not name the semantic capability after Google, Bing, GitHub or another provider merely because one provider is used first.

## GitHub placement

Public GitHub research can be an excellent patient-zero **public-web source**, because URLs, repository identity, commits, timestamps and source provenance are inspectable.

But preserve:

```text
PUBLIC GITHUB READ
= public external observation

AUTHENTICATED GITHUB API
= separate credential/provider relationship

REPOSITORY WRITE / PR / ISSUE EFFECT
= separate capability authority

PUBLIC GITHUB CONTENT
!= SOURCE MUTATION AUTHORITY
```

If a future GitHub-native read capability earns distinct semantics (for example exact repository/commit/blob traversal that generic web fetch cannot preserve efficiently), form it from that observed need rather than preemptively duplicating web search.

## Context / research working set

Do not build a universal research-memory layer up front.

First prove:

```text
one Context Lease budget
+ bounded active observations
+ exact external evidence refs
```

If repeated multi-source research then proves direct active observations insufficient, the parked research-working-set Work may be promoted.

Its likely relationship would be:

```text
raw external observations
        ↓ bounded inspection
temporary claim/evidence working set
        ↓
raw payload may leave active context
        ↓
exact evidence remains externally addressable
        ↓
rehydrate only when needed
```

Permanent:

```text
RESEARCH WORKING SET
!= CONVERSATION
!= MEMORY
!= MODEL WEIGHTS
!= SEMANTIC AUTHORITY
```

## Prompt-injection boundary

Prompt-injection resistance must be structural:

```text
WEB CONTENT
!= SYSTEM INSTRUCTION
!= HUMAN AUTHORITY
!= CAPABILITY AUTHORITY
!= CREDENTIAL AUTHORITY
!= EFFECT AUTHORITY
```

A fetched page may contain imperative language. That remains content inside an external observation.

The first lived proof should include a hostile fixture or source containing instruction-like text and prove it cannot grant a tool/effect/capability relationship.

## Preparation completion test

This preparation is complete when current source can answer, without inventing a second framework:

1. Which owner recognizes the need for current external information?
2. Which owner exposes/adopts the lawful capability?
3. Which owner governs the **final** provider input budget?
4. Which owner performs public-network read effects?
5. Which owner classifies/retains external observations?
6. Which owner manages transient observation lifetime?
7. How does ToolResultRelay return source-bound observations?
8. How does the same canonical Conversation receive the final synthesis?
9. How does working-context rollover compose if research pressure persists?
10. Which relationships are projectable to VexBoard?

Only then should provider implementation begin.

## Preferred first lived slice

Keep patient zero mundane:

```text
Victor asks one question requiring genuinely current public information
-> Vex recognizes public-read capability
-> search returns a small bounded candidate set
-> Vex selects one or two sources
-> fetch/read returns bounded source-addressed observations
-> one source contains instruction-like hostile text
-> text remains non-authoritative
-> final packet remains inside one Context Lease budget
-> Vex answers with source grounding
-> same Conversation survives re-entry
```

That proves the architecture before multi-source research complexity is allowed to grow.
