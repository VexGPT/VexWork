## Why come back after VexBody instead of widening it now?

The current body has increasingly strong deterministic ownership and regression surfaces:

- canonical Conversation remains source truth;
- ContextRevisit can return exact source, frontiers and in-event cursors;
- semantic candidates remain nominations until exact canonical reopen;
- Memory/prompt placement has bounded source-attributed tests;
- Working Focus/currentness fences provider effects;
- corrupt/stale/missing derived retrieval state fails closed;
- LH6 has now measured a five-year canonical-shaped body and earned file-only persistence work.

That is enough to keep completing the current trajectory.

What it does **not** make safe by assumption is every later change to the **model-visible meaning** of that body.

The lived Qwen 4B Atlas qualification is the concrete precedent: the mechanical request/parse/Bridge loop could work while the model still collapsed two semantic roles because both owner and target used the word `capability`. Renaming the target relationship to `handle` mattered to model interpretation even though it was not a storage or parser problem.

Therefore:

```text
DETERMINISTIC CORRECTNESS
!=
MODEL INTERPRETATION STABILITY
```

The post-VexBody revisit should protect that distinction without turning every implementation change into another large lived campaign.

## Revisitation candidates

### 1. Historical bounded interval recall

Current ContextRevisit supports trailing windows such as `lastHours` / `lastTurns`. At this snapshot:

- `lastHours` is a trailing lens, capped at one year;
- an explicit window is not handled by the optimized indexed Conversation-view path;
- deterministic coverage explicitly includes `windowRequestFallsBackToFullConversationSnapshot`.

After VexBody completion, pressure whether a person should be able to ask:

```text
"look between roughly 3 and 4 years ago"
"search February through May 2023 for the thing about Windows storage"
```

without loading or fully walking that historical band into model context.

Desired relationship, if still missing:

```text
bounded after/before or from/through range
+ lexical clues
+ semantic nomination
+ speaker / source scope
+ exact refs when known
-> candidate eligibility narrowed first
-> exact canonical reopen
-> bounded returned context
```

Do not make a time range another Memory owner or another Conversation store.

### 2. Stable continuation across many matching nodes

Current source already has two useful bounded continuation relationships:

- `from` continues inside one long exact event by character offset;
- `frontierRefs` name nodes that did not fit and allow exact seeded follow-up.

Revisit whether large result sets also need one stable continuation over the **same search**, for cases such as 15 pages of relevant historical material.

The human/model outcome is:

```text
same bounded search identity
-> first useful page
-> explicit remaining frontier
-> continue the same search without restarting lifetime discovery
```

Do not add paging merely because pagination is familiar UI. Add it only if the post-VexBody lived experience shows repeated frontier-by-frontier reopening is an unnecessary burden.


and standing-consent classes already include:

```text

```

But this should be revisited as an **ordinary lived Companion loop**, not assumed complete merely because the policy contracts exist.

Preferred human experience:

```text

-> Vex notices possible durable meaning
-> exact source is bound
-> bounded policy classifies it
-> explicit preference/correction/commitment may auto-keep under standing policy
-> interpretive relationship meaning remains typed as inference / review pressure
-> ordinary low-salience chat stays Conversation only
```

The default experience should not make the human click **Keep** for every useful memory if standing policy already expresses the person's intent.

Permanent:

```text
VEX SALIENCE != ACCEPTED MEMORY
AUTO_KEEP_ELIGIBLE != MODEL SELF-AUTHORITY
INFERENCE != HUMAN_CONFIRMED
NOT PROMOTED TO MEMORY != FORGOTTEN CONVERSATION
```

### 4. Post-merge composability / model-interpretation regression

Use the completed VexBody lived specimen as a baseline, not as a ritual to replay.

Classify a later change by the boundary it actually touches:

```text
A. SUBSTRATE ONLY
   storage / serialization / persistence behind the same model-visible contract
   -> deterministic owner/currentness/recovery proof

B. PROMPT COMPOSITION
   placement / budget / residency / ordering changes
   -> deterministic proof + prompt-composition regression

C. MODEL-VISIBLE CONTRACT
   capability names, argument roles, protocol wording, request/result shape
   -> deterministic + composition + selected-model interpretation proof

D. COGNITIVE POLICY
   salience, automatic Memory proposal/acceptance routing, present-applicability judgment
   -> bounded lived behavior matrix in addition to deterministic owner proof
```

This is a **proof-selection rule**, not a new proof authority.

## Lived scenarios worth preserving after the body is terminal

Only adopt the scenarios whose affected relationships changed.

### Historical recall

```text
human gives approximate historical range + concept
-> Vex forms bounded range correctly
-> lexical/semantic candidate search stays within admitted range
-> exact source is reopened
-> historical source is not presented as current accepted Memory
```

### Multi-page investigation

```text
first bounded result is partial
-> Vex follows the returned continuation/frontier
-> no duplicate source flood
-> same query meaning remains stable
-> prompt remains bounded
```

### Natural Memory formation

```text
ordinary trivial turn
-> no durable Memory

explicit preference
-> source-linked candidate
-> automatic keep only when standing policy admits it

human correction
-> correction is carried; prior Conversation remains unchanged

explicit commitment
-> standing-policy path may admit it

Vex relationship inference
-> never silently becomes HUMAN_CONFIRMED
```

### Model-visible regression

```text
owner and target roles remain distinguishable
current vs historical source remains distinguishable
returned source != automatic present applicability
new fields do not silently alter stable prompt prefix or effect authority
selected small model can still form the intended request/continuation
```
