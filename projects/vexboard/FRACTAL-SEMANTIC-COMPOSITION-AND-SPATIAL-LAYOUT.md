### Width-bounded local continuation is a foundation constraint

Local composition must not assume that a ROW or COLUMN can propagate forever in one direction.

The container's current projection bounds are already the local spatial constraint. When an explicitly
bounded flow reaches that edge, the resolver may continue inside the same container without changing
BoardGraph containment, relationship meaning, or structural order.

The first earned continuation policies are deliberately small:

```text
FAIL
  preserve the original behavior
  -> a linear ROW/COLUMN that exceeds its container fails closed

WRAP
  preserve ordered children
  -> start the next local row / column at the normal leading edge

SERPENTINE
  preserve ordered children
  -> alternate local reading direction on each new row / column
  -> useful for zig-zag / course / process flows where returning to the far edge would waste space
```

Permanent:

```text
CONTAINER_BOUNDS = LOCAL_PROJECTION_CONSTRAINT
BOUNDARY_CONTINUATION != SEMANTIC_REPARENT
BOUNDARY_CONTINUATION != STRUCTURAL_REORDER
SERPENTINE_DIRECTION != FLOW_DIRECTION
RESOLVED_PATH_SHAPE != PROCESS_TRUTH
```

A spiral, radial sweep, obstacle-aware continuation, or another path shape may be added later when a
real consumer earns it. The foundation seam is **explicit local boundary policy**, not a promise that
one algorithm is correct for every map.

This keeps the small-system and large-system cases on the same contract:

```text
few children
-> ordinary local ROW / COLUMN

many children inside bounded container
-> same stable identities + same structural order
-> local continuation strategy
-> no giant horizontal canvas required
```


### Locality is part of correctness

A small edit should not randomly rearrange the understood board:

```text
small semantic / layout edit
-> preserve explicit anchors
-> inspect local occupancy
-> create room near affected region
-> move smallest necessary neighborhood
-> reroute affected connectors
-> preserve unrelated regions
```

### Connector routing is projection reasoning

Relationship direction remains semantic; visible route is projection.

Candidate routes should be ranked against current geometry using pressures such as:

```text
obstacle collision               forbidden / very high
node/container penetration       forbidden unless admitted
edge crossing                    high
label collision                  high
insufficient clearance           high
unrelated anchor movement        high
bend count                       moderate
route length                     moderate
preserve prior accepted route    preferred
lens reading direction           preferred when applicable
```

Do not freeze arbitrary numeric weights before proving cases earn them.

### Hover, context menu and pinned diagnostic focus

The full system graph may contain far more relationships than should be drawn at once.

Prefer an interaction grammar that reveals context on demand:

```text

-> inspect / trace upstream / trace downstream / where used

PIN_SET
-> presentation-owned diagnostic focus set
-> preserve selected stable refs
-> compute a bounded relational neighborhood or connective path
-> emphasize only the relationships needed to explain those refs together
-> de-emphasize unrelated canvas meaning
```

Pinning is not semantic authoring:

```text
REVEAL != PIN
PIN != SELECT
PIN != JOURNEY
PIN != SEMANTIC_GROUP
PIN_SET != BOARD_GRAPH_MUTATION
PIN_SET != SOURCE_OWNERSHIP
COMPUTED_RELATIONAL_PATH != NEW_RELATIONSHIP
```

Default pinning should target semantic identity so every visible occurrence of that identity can participate. When debugging a projection-specific ambiguity, the interaction may explicitly pin one projection occurrence instead.

Useful bounded pin-set views may eventually include:

```text

  relationships directly among pinned refs

CONNECT
  smallest useful bounded semantic paths connecting pinned refs

UPSTREAM
  what produces / feeds / owns the pinned refs

DOWNSTREAM
  what consumes / renders / depends on the pinned refs

OCCURRENCES
  where the pinned identities appear in the current projection / reachable boards
```

These are interaction/view hypotheses, not a mandate to add a persisted pin schema now. First prove the behavior with current reveal, graph query and projection boundaries.

### Journey pathway calculation and reduction snapshots

Flow loops are already valid BoardJourney history and meaningful repeated visits must remain exact raw evidence.

The next useful analytical layer is therefore derived rather than destructive:

```text
RAW_BOARD_JOURNEY
  -> exact traversal evidence
  -> repeated visits remain literal

CALCULATE_PATHWAYS
  -> derive closed ordered relationship motifs
  -> intern repeated motifs inside one analysis snapshot
  -> form a reduced walk that references motif identity
  -> preserve expandability back to raw occurrences
```

Permanent distinctions:

```text
RAW_JOURNEY != REDUCED_JOURNEY
LOOP_MOTIF != LOOP_OCCURRENCE
LOOP_LABEL != LOOP_IDENTITY
LOOP_REFERENCE != DELETED_EVIDENCE
SAME_NODE_SEQUENCE != SAME_RELATIONSHIP_SEQUENCE
REPEATED_PATTERN != WASTE
REDUCTION_CANDIDATE != AUTOMATIC_PROCESS_JUDGMENT
CALCULATE_PATHWAYS != JOURNEY_MUTATION
```

Motif recognition should use exact ordered semantic traversal coordinates, especially `relationshipRef` order, rather than labels or visual node names.

Example:

```text
raw:
  a -> b -> d -> a
  a -> c -> d -> a
  a -> b -> d -> a

derived motifs:
  Loop 1 = [rel.a-b, rel.b-d, rel.d-a]  x2
  Loop 2 = [rel.a-c, rel.c-d, rel.d-a]  x1

reduced walk snapshot:
  Start a
  -> Loop 1 occurrence 1
  -> Loop 2 occurrence 1
  -> Loop 1 occurrence 2
```

A `Calculate pathways` action may expose this as an ephemeral analysis of the current Journey.

The existing reveal/highlight system is the preferred presentation seam:

```text
hover/focus Loop 1
-> highlight motif semantic refs
-> highlight exact motif relationship refs
-> retain the surrounding board for context
```

This supports future company/process analysis such as repeated rework, retry, approval, quality or operational patterns without prematurely declaring those repetitions waste. Source-owned duration, actor, condition, outcome or policy evidence may later strengthen interpretation.

A useful company-facing framing is:

> reveal repeated ordered process motifs, show where they recur in the real map, and expose reduction opportunities without erasing the underlying journey evidence.
