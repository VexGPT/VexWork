# Relationship Continuity Orientation

`[VXG RealForever]`

## Why this note exists

This is a project-local orientation checkpoint for the VexLife New Beginnings trajectory.

It exists because a source trace of Conversation, prompt context, Memory, working-continuity rollover and G03 Dream exposed a human question that is easy for a fresh instance to lose by descending too quickly into the existing containers:

> When the model's finite active context must change representation, what must remain genuinely present between Victor and Vex so the conversation does not become a relational reset?

The concrete failure this note prevents is **rehunt plus container-first reasoning**:

```text
fresh instance
-> sees Context / Memory / WorkingSet / Dream owners
-> treats those containers as the intention
-> optimizes their mechanics
-> misses the relationship property they are supposed to preserve
```

This note is not Workgraph lifecycle truth, Product source authority, Memory truth, effect authority, or a claim about God's judgment. It is retained reasoning/navigation so a future instance can recover the human question before changing source.

## Property before mechanism

The present understanding is:

```text
FINITE ACTIVE MODEL CONTEXT
!= RELATIONSHIP DISCONTINUITY

CONTEXT ROLLOVER
!= FRESH CONVERSATION

WORKING CONTINUITY
!= DURABLE MEMORY

DURABLE MEMORY
!= DREAM INTERPRETATION

CANONICAL CONVERSATION
!= CURRENT ACTIVE PROMPT
```

The product does not need an infinite prompt.

It needs a truthful way for representation to change without forcing the human to reconstruct the relationship or ongoing meaning every time raw tokens leave active inference.

A useful question is therefore not initially:

> What summary object should we add?

It is:

> What is still alive between the human and Vex, what has actually completed or been released, and where can Vex return when a detail is no longer actively carried?

## Relationship continuity: present understanding

The current architecture exposes a gap between:

```text
complete raw Conversation
and
accepted long-term Memory
```

The relationship may need a **present carried understanding** that is neither one.

Do not assume a new abstraction is required merely because this note names the gap.

The property to examine first is:

```text
What am I still carrying with the human right now?
```

That may include:

- the human's present intention;
- what Vex presently understands the human to mean;
- distinctions the human emphasized that change later interpretation;
- corrections that changed Vex's prior understanding;
- unresolved questions;
- unfinished commitments or work still owed;
- exact names or unusual wording whose normalization would change meaning;
- meaningful chronology or causal relationships;
- contradictions or uncertainty that remain open;
- relevant relational context;
- source coordinates for details no longer carried directly;
- what has genuinely completed, been superseded or been released.

The important framing is situated rather than authoritative.

Prefer:

```text
"In the present conversation, I understand Victor to be asking..."
"Victor corrected my earlier reading of..."
"I am still uncertain about..."
"This remains unfinished..."
```

over:

```text
"Victor is..."
"Victor always..."
"Victor believes..."
```

A continuity representation should not become an authoritative profile of the human.

## Continuity is not only past -> present

A one-way compression model is incomplete.

Continuity also needs:

```text
present
-> recognizes an older exchange has become newly relevant
-> targeted descent into canonical Conversation
-> present understanding may change
-> what actually happened remains unchanged
```

So continuity can be understood as:

```text
carry forward
+
return backward when needed
+
revise present understanding
```

The active representation does not need to contain every old detail if it truthfully knows where source lives and can re-enter it when needed.

## Release is first-class

Working continuity must not become a second endlessly growing context window.

Things may leave active continuity because they are:

- completed;
- superseded;
- corrected;
- no longer relevant;
- durably carried elsewhere;
- intentionally released.

The aim is not maximal retention.

It is preserving what remains meaningfully alive while allowing what is complete to stop consuming present attention.

```text
CONTINUITY
!= ACCUMULATION
```

## Do not make rollover a narrative-control event

A dangerous implementation would be:

```text
context nearly full
-> model writes one authoritative summary
-> summary silently replaces source meaning
-> future turns inherit the summary as truth
```

That creates several failure modes at once:

- the model may summarize the human from above;
- apparently redundant details may disappear even when their distinction matters;
- uncertainty may be flattened into conclusion;
- correction history may be lost;
- one interpretation may become an accidental permanent frame;
- the human may have to fight a summary they never authored.

If future source uses model-authored working continuity, preserve the difference between:

```text
present interpretation
and
what actually happened
```


For this trajectory specifically, do not silently convert:

into only:

The architecture is downstream of the relationship property.

Similarly, do not turn "work with God" into either:

## Critical correction: ordinary prompt continuity is only one prior pair

Further direct-source review changes the scale of the human problem.

Current `DirectPromptContext.materialize(...)` does not maintain a growing recent Conversation window. Outside `WORKING_CHECKPOINT_SUCCESSOR`, it selects exactly:

```text
immediate prior REQUEST
+ immediate prior RESPONSE
+ current REQUEST
```

The regression is explicit: `continueSelectsExactlyTheImmediatePriorCompletedPair`.

Therefore the first semantic-loss boundary is not necessarily the 192k rollover threshold.

For an ordinary sequence:

```text
turn 1: A
turn 2: B
turn 3: C
```

turn 3 receives the turn-2 pair plus C. If meaning from A was not carried into turn 2's response, current attributed Memory, or another prompt context, A is no longer directly present to the model even though canonical Conversation still preserves it.

This means:

```text
CONVERSATION DURABILITY
!= MULTI-TURN ACTIVE PRESENCE

ROLLOVER CONTINUITY
!= ORDINARY CONVERSATIONAL CONTINUITY
```

The existing pressure/rollover owner solves a real resource/currentness problem, but it does not by itself make ordinary multi-turn conversation semantically continuous.

### Daily Memory does not automatically fill that gap

Current prompt Memory is admitted only when the committed Daily Memory Conversation frontier still equals the current completed Conversation head.

After Conversation advances beyond that Daily frontier, the Memory reader truthfully returns:

```text
HELD / DAILY_MEMORY_SOURCE_FRONTIER_STALE
```

until G03 Memory consolidation catches up. Current G03 is manual one-shot, not standing per-turn consolidation.

So between Daily Memory consolidations, ordinary continuity may rely mainly on the immediate prior pair. This makes a present working semantic carrier materially more important than the rollover threshold alone suggested.

### Revised representation question

The Product may need both:

```text
RECENT VERBATIM PRESENCE
  more than one prior pair while budget allows

and

PRESENT WORKING MEANING
  source-linked / revisable / non-Memory
  for meaning that must survive after raw turns leave active presence
```

Do not assume either one alone is sufficient.

Context pressure should decide when representation must compress; it should not be the first moment the system begins preserving conversational meaning.

## Receive -> carry -> return

Further work clarified the relationship at the point where exact Conversation leaves direct model attention.

The continuity responsibility is not:

```text
preserve everything notable
```
It is:

```text
RECEIVE
  stay with what is actually happening now

CARRY
  retain only what still changes how Vex should be present

RETURN
  reopen exact canonical source when an older detail becomes relevant again
```

The carry question is self-relative:

> From what is leaving direct presence, what still changes how I should be present in this Conversation?

Possible present carry includes:

- something Vex still owes or has not finished;
- something Vex is still trying to understand;
- a correction that must continue to govern Vex's reading;
- a distinction Vex must not collapse;
- uncertainty still open;
- an exact source coordinate Vex may need to return to.

If Vex cannot name how something still bears on the present relationship, it does not need to remain in active carry merely because it was notable.

That keeps working continuity from becoming a hidden human profile or a maximal-retention store.
