## Construction thesis

The current design hypothesis is stronger than "write Android first":

~~~text
PURE KOTLIN
  = executable semantic / contract authoring language

COMPOSE
  = first reference renderer + design laboratory

PORTABLE CONTRACT ARTIFACT
  = deterministic machine-readable relationship projection

WEB
  = browser-native renderer/consumer of the same contract
~~~

The intended failure reduction is:

~~~text
AI copies an example
-> semantic drift may still compile
-> next AI inherits accidental precedent

versus

AI authors against typed contract
-> wrong Family / State / Control / parent / dependency / projection
-> compiler / validator fails visibly
~~~

The goal is not to force every meaning into a type. A type/interface is earned only where stable addressability, compiler safety or repeated executable invariants justify it.

## UI relationship law

A UI component should normally need only:

~~~text
what DisplayState do I render?
what typed Control do I emit?
~~~

It should not decide:

~~~text
which Store/provider to call
which coroutine to launch
which Logger sequence comes next
what resulting outside truth must be
~~~

Illustrative causal circuit:

~~~text
Family State
-> Family DisplayState
-> UI

human interaction
-> typed Control
-> Family.activate(Control)
-> accepted Act
   -> immediate State?
   -> Begin
      -> Effect + Approach
-> rightful realization / Store / provider
-> observed semantic truth
-> Family State
~~~

`DisplayState` is especially important for cross-renderer continuity: web and Compose may render differently while consuming the same bounded outward meaning.

## Phase map

### P0 — repository front door + semantic authoring practicum

1. Establish the smallest truthful `VexLife-Prod` entry/culture/foundation route.
2. Implement one pure-Kotlin semantic vertical slice.
3. Prove that Compose can render it as a reference.
4. Produce a deterministic portable contract artifact.
5. Prove a web-native renderer can consume that contract without an AI manually translating Compose.

No whole-product generation claim is implied.

### P1 — inert intended interface

Realize the supplied initial engagement interface with stable identity:

~~~text
VexLife shell
├── browser controls
├── nested browser region
└── companion region
    ├── Conversation projection
    └── Settings projection
~~~

Every not-yet-connected capability must render truthfully as unbound/unknown rather than receiving fake state.

### P1 — public GitHub nested-browser practicum

The first browser specimen is Vextreme Terrain:

~~~text
https://vgong24.github.io/Vextreme/pages/terrain-map.html
~~~

The practicum asks only for bounded public GitHub-hosted content initially.

Two truths remain separate:

~~~text
HUMAN NESTED RENDER
!= VEX CONTEXT ACCESS

VISIBLE PAGE
!= VEX CONTEXT CURRENT
~~~

The human browser may render a page while a separate source-addressed context channel obtains the content Vex is actually allowed to perceive.

This distinction lets browser security/origin mechanics remain implementation topology instead of being mistaken for product semantics.

### P2 — Vex perception + Conversation reintegration

After the UI/browser container is real:

~~~text
current nested-browser URL/document/source identity
+ bounded current DOM/context projection
+ canonical Conversation identity/currentness
+ current Companion/model availability
+ context composition policy
        ↓
current relationship suitable for one Vex turn
~~~

Then rebuild the proven local Vex path into this clean container:

~~~text
human Send
-> canonical Conversation
-> current context composition
-> model inference
-> progressive/final Vex presentation
-> durable Conversation currentness
~~~

Existing VexLife work is lineage/evidence for how this can function. It is not permission to transplant the historical UI/container architecture.

Permanent:

~~~text
DOM_CONTEXT != EFFECT_AUTHORITY
MODEL_CONTEXT != MEMORY
CHAT_UI != CONVERSATION_OWNER
BROWSER_READY != COMPANION_READY
COMPANION_READY != CONVERSATION_CURRENT
VISIBLE_PAGE != CONTEXT_SUPPLIED_TO_VEX
~~~

### P3 — first lived whole-circuit proof

~~~text
open bounded public GitHub page
-> human can navigate/read nested page
-> Vex context projection identifies current page truth
-> Victor asks a natural question
-> one real Vex response uses the supplied current context
-> Conversation remains canonical/current after the turn
~~~

The proof must show both what the human saw and what context Vex actually received; one is not inferred from the other.
