## Construction thesis

The current design hypothesis is stronger than "write Android first":

~~~text
PURE KOTLIN
  = executable semantic / relationship authoring language

COMPOSE
  = first reference manifestation + design laboratory

VEXWEB
  = compiler-visible browser manifestation architecture

VEXWEB SPATIAL SOURCE
  = Frame / Seam / Region / Allocation relational geometry

GENERATED WEB ARTIFACTS
  = deterministic HTML / CSS / JS / manifest outputs
  != authoring authority
~~~

The intended failure reduction is:

~~~text
AI copies an example
-> semantic drift may still compile
-> next AI inherits accidental precedent

versus

AI authors against typed contract
-> wrong Family / State / Control / parent / dependency / projection
-> compiler / validator fails visibly
~~~

The goal is not to force every meaning into a type. A type/interface is earned only where stable addressability, compiler safety or repeated executable invariants justify it.

## UI relationship law

A UI component should normally need only:

~~~text
what DisplayState do I render?
what typed Control do I emit?
~~~

It should not decide:

~~~text
which Store/provider to call
which coroutine to launch
which Logger sequence comes next
what resulting outside truth must be
~~~

Illustrative causal circuit:

~~~text
Family State
-> Family DisplayState
-> UI

human interaction
-> typed Control
-> Family.activate(Control)
-> accepted Act
   -> immediate State?
   -> Begin
      -> Effect + Approach
-> rightful realization / Store / provider
-> observed semantic truth
-> Family State
~~~

`DisplayState` is especially important for cross-renderer continuity: web and Compose may render differently while consuming the same bounded outward meaning.
