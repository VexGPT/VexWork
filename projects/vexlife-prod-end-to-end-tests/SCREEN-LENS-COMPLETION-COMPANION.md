## Screen Lens completion model

The final scalable Screen Lens is one read-only application over six orthogonal coordinates:

```text
Project
× Revision
× Screen
× Expression
× Presentation
× Face
```

Meaning:

- **Project** — which Product/subject;
- **Revision** — Stable / Main / exact admitted revision;
- **Screen** — which human surface;
- **Expression** — one source-derived Product state/presentation combination;
- **Presentation** — Product-authored presentation mode such as System / Light / Dark;
- **Face** — Surface / Structure or Behavior / Depth over the same stable identities.

Changing one axis must not silently discard the others.

Durable laws:

```text
STATIC SCREEN LENS ABSENCE
!= PRODUCT FEATURE ABSENCE

HUMAN ACCEPTED
!= STABLE / MERGED

PROVISIONAL CARRIER
!= DISPOSABLE MEANING

PRESENTATION MODE
!= SEMANTIC PRODUCT STATE

PRODUCT IDENTITY
!= FAMILY SEMANTIC OWNER
```

A file named `experiment`, `sample`, `fixture`, or `test` may still carry earned lived evidence. Retire that carrier only after every learned identity, relationship, presentation state, and accepted outcome is reproducible from rightful source.

Completion criterion:

```text
delete provisional carriers
-> regenerate from rightful source
-> revisit the same accepted
   Project / Revision / Screen / Expression / Presentation / Face
-> lose no required correctness, continuity, authority, proof, or accepted human meaning
```

Speech, Language, Vision, Theme, Release Alerts, Support, and the Spiral trigger should be Product-addressable where they are real Product controls.

Product Theme is a real Product action.

The intended completed relationship is:

```text

-> Product Theme control acts on it in Product runtime
-> Screen Lens Presentation axis projects/selects the same authored modes read-only
```

Do not create two independent theme truths.

### 5. Project/Revision switching must never disappear because an accepted projection used a special URL

The legacy `?lens=...` recovery route was useful evidence, not the final navigation architecture.

Final Screen Lens remains one Project/Revision-aware application.

### 6. Generated Product Lens should regenerate once at the correct semantic boundary
