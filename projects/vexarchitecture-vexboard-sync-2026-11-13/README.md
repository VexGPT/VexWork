## Stable architecture comparison grammar

The public VexArchitecture teaching accepted on 2026-11-13 says the reusable questions are:

```text
Family
    semantic / product meaning

Method
    bound realization

Execution
    active custody when earned

Partner
    independently-owned external participation when earned

Store / provider
    outside truth

Relay / convergence
    new relationship truth from independently-owned truths

Dependency / construction
    lifetime + object construction

Logger / chronology
    what actually happened and in what order

Service / platform host
    sustained concrete realization
    != semantic owner

Presentation
    human-facing meaning
    != source truth
```

The architecture law is question-first:

```text
CURRENT PLACEMENT != AUTHORITY BY EXISTENCE
SAME NOUN != SAME RELATIONSHIP
REPOSITORY / STORE TERMINAL != AUTOMATIC PROJECTION GAP
PARTNER != MANDATORY OUTSIDE-TRUTH WRAPPER

SOURCE PROVES DEEPER RELATIONSHIP
+ LENS STOPS EARLY
-> PROJECTION GAP

SOURCE ENDS AT RIGHTFUL PROVIDER / STORE BOUNDARY
-> KEEP THE TERMINAL
```

## Audit method

### Pass A — Screen and control census

For each of the 13 current screens:

1. enumerate registered/realized elements;
2. distinguish interactive controls from content/containers;
3. resolve every pathway-bearing control;
4. record controls that are intentionally held/unprojected;
5. do not treat every element without a pathway as missing behavior.

### Pass B — Pathway relationship walk

For each of the 71 current pathways:

```text
Surface
  what does the human see/touch?

Structure
  what source/container/identity owns it?

Behavior
  what does the interaction mean?
  who owns the semantic decision?

Depth
  what realizes it?
  what outside truth participates?
  how does truth return?
```

Follow exact source, not labels alone.

### Pass C — Depth terminal check

For every path with Depth, classify its terminal:

```text
RIGHTFUL_TERMINAL
    current source really ends at this provider/store/realization boundary

RETURN_COMPLETE
    source return to Family/Projection is perceptible

PARTNER_COMPLETE
    external participant is visible through the source-earned
    Partner / Connection / Conversion / Signal / Observation / Receiver chain

HELD_SOURCE_AMBIGUOUS
    source relationship exists but cannot be projected truthfully yet

PROJECTION_STOPS_EARLY
    current source proves a deeper/rightful relationship that Lens omits
```

Priority witnesses:

```text
VexStream Playback
    current Direct Family
    -> Method / Execution
    -> Player Partner request
    -> later Player Signal
    -> Store
    -> same Family

CGM / Insulin Partner labs
    Partner
    -> Connection
    -> Conversion
    -> Source / Signal
    -> Observation / Receiver
    -> Store
    -> source-addressed observation / Family consequence

Store-ending direct registrations
    review individually
    never upgrade to Partner by analogy
```

### Pass D — newer stable relationships

Ask whether current Screen Lens makes these relationships perceivable where source earns them:

```text
Service-host sustained realization
Widget / system-surface manifestation
Relay / convergence
construction/lifetime
chronology
presentation return
```

Do not add a `SERVICE`, `WIDGET` or `RELAY` role merely for naming symmetry. Existing role/edge vocabulary may already be enough.

### Pass E — repair only proven gaps

A repair must name:

```text
screen / control / pathway
exact Android source evidence
current Lens projection
missing or misleading relationship
smallest rightful VexBoard owner
regression proof
generated-currentness consequence
```

Permanent:

```text
VEXBOARD REPAIR != ANDROID SEMANTIC REWRITE
LENS JSON != HAND-AUTHORED SOURCE
PUBLIC DOC WORDING != LENS SOURCE INPUT
CURRENT SOURCE RELATIONSHIP -> PROJECTION
NOT
DESIRED PROJECTION -> INVENTED SOURCE RELATIONSHIP
```
