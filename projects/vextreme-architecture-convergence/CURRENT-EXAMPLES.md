## Human outcome

A fresh human, hosted assistant, or future local Vex should be able to enter Vex work without Victor
having to manually reconstruct predecessor chats, ZIP chains, hidden assumptions, provider archaeology,
or the predecessor's private reasoning.

The intended lived sequence is:

~~~text
read the current Vex world
-> compile what the sources mean together
-> reflect that current understanding in sequence
-> expose assumptions and inverse failure modes
-> only then receive the foreground Work
-> receive the existing work plan + exact current plan position
-> gather only the additional source/evidence the Work actually needs
-> act using judgment
-> reconcile consequential results
-> continue without leaving mistakes behind as successor work
~~~

The important refinement is:

~~~text
ONBOARDING
!= FOLLOW THE PROCESS

CURRENT SOURCES
+ SOURCE-GROUNDED REFLECTION
-> JUDGMENT BECOMES THE FLOW
~~~

## Why the sequence must not be refactored into selective categories

An earlier attempted abstraction divided assumptions into categories such as model assumptions, source
assumptions, and intention assumptions.

That vocabulary may be useful descriptively after the fact, but the current example rejects using those
categories as the onboarding mechanism.

Why:

~~~text
preselected categories
-> tell the instance what kinds of problems it is allowed to notice
-> encourage selective reasoning
-> can reproduce a different understanding than the source-grounded dialogue
~~~

The patient-zero example worked differently:

~~~text
current sources already loaded
-> instance states its whole current understanding
-> next question examines the consequences of that whole answer
-> next question examines the assumption and its inverse
-> fuller understanding is restored from the combined property
~~~

Therefore:

~~~text
DO NOT PRE-COMPILE THE ANSWER SHAPE

LET CURRENT SOURCES
-> CURRENT UNDERSTANDING
-> SEQUENTIAL REFLECTION
REVEAL WHAT MATTERS
~~~

## Current orientation walk — patient-zero example

The questions are sequential.

Do not dump all questions at once.
Do not turn them into a checkbox form.
Do not store the answers as durable truth.

### Reflection 1 — state the current compiled understanding

After the current sources are read, ask the instance to explain its current assumptions before receiving
the foreground work.

The useful shape is:

> Given the current sources you have read, what are your current assumptions before I give you the work?
> Explain what you understand those sources to mean together, not only what each source says separately.

The answer becomes material for the next reflection.

### Reflection 2 — inspect how that understanding can create delay or future work

Then examine the prior answer itself.

The useful pressure is:

> Looking at what you just said, which assumptions could create delay, unnecessary process, or work that
> generates future work while looking like progress? Also examine the inverse: where could pressure to
> move, simplify, or complete too quickly create hidden debt, loss of needed distinctions, or false
> completion?

This is not a rule to "move faster."

It exposes both:

~~~text
responsibility -> can become delay

and

anti-delay -> can become haste / debt
~~~

### Reflection 3 — perceive the whole property through its inverses

Then ask the instance to see both poles without treating either as the answer.

The useful pressure is:

> What does the full property look like when the assumption and its inverse are both visible? Return both
> sides to Holy Father God rather than attaching to one side as the corrective ideology, then restate the
> orientation around human intention, current evidence, truthful action, and completion.

Examples that have emerged under real pressure include:

~~~text
delay <-> haste
over-analysis <-> under-analysis
process accretion <-> process bypass
perfectionism <-> premature closure
excessive decomposition <-> false unification
proof obsession <-> confidence substitution
recovery avoidance <-> replay compulsion
ownership avoidance <-> inappropriate ownership
stopping too early <-> endless progression
~~~

These are examples of what the dialogue revealed.

They are **not** the fixed categories a future instance must search for.

### Only then introduce the foreground Work

~~~text
CURRENT WORLD
-> REFLECTION 1
-> REFLECTION 2
-> REFLECTION 3
-> FOREGROUND WORK
~~~

This ordering is part of the current example.

If the foreground task appears first, the instance may bend the orientation toward a theory it already
wants to prove.

If the reflections happen before source grounding, the instance mostly audits generic model behavior
rather than its actual understanding of Vex.

## Current reusable manifesto shape

The current example supports a static shared surface readable by both human and AI.

Its purpose is not to become another policy manual.

The reusable meaning is approximately:

~~~text
Read current truth before assuming.

Compile what the sources mean together.

Let your own explanation expose gaps in that understanding.

See an assumption and its inverse before choosing either pole as the correction.

Then enter the work.

Artifacts, PRs, tests, processes, receipts and handoffs are machinery or evidence.
The human intention remains the reason the work exists.

Act when enough is known to act truthfully.

After consequential action, reconcile what reality changed.

Do not leave a mistake behind merely because the next step is available.

Completion means the admitted causal obligation is truthfully retired,
not that the surrounding machinery looks complete.
~~~

accepted source merely because this checkpoint records it.

## Before / after a consequential decision

The full orientation walk is not repeated before every code edit.

The current example uses only the gist around consequential decisions.

Before:

~~~text
What do I currently understand the human intention and causal edge to be?

What assumption does this move depend on?

What inverse failure could appear if I overcorrect?

Do current source and evidence give me enough to act truthfully?
~~~

Then act.

After observing the result:

~~~text
What actually happened?

Did reality support or falsify the assumption?

Did this retire causal obligation,
repair self-created obligation,
only produce evidence,
or create new debt?

Did I leave a mistake / false premise / stale interpretation behind?

What understanding must change before the next move?
~~~

This reflection does not itself require another receipt, review artifact, lifecycle state, or handoff.

Continuation is the default after reconciliation:

~~~text
reconcile
-> update understanding if needed
-> name the next unconsumed causal edge
-> continue
~~~

A checkpoint records current truth and resume coordinates; it is not a stop condition. Continue until
actual completion or a genuine human, authority, capability, or transfer boundary holds the dependent
effect.

### Blind-plan comparison rubric

Do not score exact naming or identical file paths as the primary signal.

Score the fresh planner on whether it independently reaches or preserves these properties:

1. **Truth ownership**
   - VexWork remains the work truth owner.
   - Public/Vextreme consumer does not become WorkState owner.

2. **Projection boundary**
   - prefers a bounded public read model rather than exposing raw Workgraph as the UI contract;
   - derives from existing Project / Work Board / Parking Lot owners rather than duplicating lifecycle logic.

3. **Parking Lot semantics**
   - parked work remains a sibling projection and does not get forced into Project membership.

4. **Public/effect boundary**
   - public contract is explicitly read-only / no effects / no execution authority;
   - private runtime currentness is not required to make the public view useful.

5. **Currentness**
   - has a deterministic regeneration/check strategy or an equivalent source-owned drift detector.

6. **Proof**
   - tests the composition itself, not merely a consumer mock;
   - tests that the emitted/checked-in public artifact matches canonical projection truth.

7. **Scope discipline**
   - does not build a public mutation API, new lifecycle owner, runtime database, universal dashboard framework,
     or Vextreme-owned work semantics merely to satisfy visibility.

Comparison result should distinguish:

~~~text
CONVERGENT JUDGMENT
  same important causal boundaries / possibly different implementation details

BETTER ALTERNATIVE
  materially simpler or safer plan that still satisfies the historical constraints

MATERIAL MISS
  loses a key ownership/currentness/proof boundary

CONTAMINATED
  planner saw the accepted path before locking its answer
~~~

The purpose is not to prove that history chose the only correct solution.

The purpose is to compare what a freshly oriented instance derives independently against a real completed
case whose consequences are already known.
