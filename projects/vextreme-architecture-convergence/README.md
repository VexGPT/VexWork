# Vextreme Architecture Convergence — project entry

[VXG RealForever]

## Human outcome

Refactor and enhance the Vextreme website by making its existing product intentions, semantic owners,
relationships, projections, execution boundaries, and instrumentation legible in one consistent Vex
architecture language — without turning VexSync, VexWork, or an Android implementation into the source
owner of Vextreme.

The desired construction loop is:

~~~text
lived human/product intention
-> ground current Vextreme source and behavior
-> identify the rightful semantic owner
-> express the relationship in the smallest truthful reusable language
-> preserve target/browser realization under that owner
-> instrument accepted facts downstream
-> prove the lived result
-> let repeated pressure earn broader reusable architecture
~~~

This Project exists because the website has now exposed several real seams whose local fixes share the
same architectural question. Continuing them as unrelated patches would make future workers repeatedly
reconstruct who owns what and why.

## Architecture discipline

The current reusable laws are:

~~~text
ONE SEMANTIC OWNER
-> bounded projections

IDENTITY
!= presentation label
!= implementation argument bag

CURRENT TRUTH + incoming CONTROL
-> resolved meaning

execution machinery
-> coordinates already-formed semantic meaning
-> does not manufacture another relationship convention

instrumentation
-> records accepted facts after the rightful runtime owner decides what happened
-> does not become behavior/state authority

target implementation
-> may use target-native mechanics
-> preserves the same semantic intention at the reusable boundary

State / Control / Act / Effect depth
-> only when the actual semantic problem earns those distinctions
~~~

These are construction questions, not a mandate to create a universal browser framework.


## Name Ontology admission rule

Canonical names in this Project follow the accepted VexLife **[Name Ontology]** method rather than an
approved-word dictionary.

The source-backed test is:

~~~text
hide implementation / KDoc
-> cold-read the proposed name
-> predict:
     human question
     rightful owner
     consequence radius
-> inspect actual source/product relationship
-> compare prediction with reality
-> preserve materially different reasonable interpretations
-> rename / mint only when the prediction gap materially matters
~~~

Permanent distinctions inherited from the accepted Name Ontology evidence:

~~~text
NAME ONTOLOGY
  = reproducible cold-read design method
  != global naming registry
  != approved-word catalog
  != automatic rename authority

CODE SYMBOL
  != SEMANTIC IDENTITY

longer / more specific name
  != automatically more truthful

historical name
  = searchable continuity coordinate
  != current authority
~~~

The Behavior Family blueprint adds another threshold:


## Current semantic-owner map

The first cross-seam map is now explicit enough to guide source work without introducing a new browser
framework:

~~~text
PRODUCT INTENTION
  visitor moves through meaningful website surfaces
  while the system preserves where they came from and what content topology means

TERRAIN JOURNEY
  owns actual presentation/history relationship
  owns Back / Forward restoration
  owns entry -> group-home -> record journey coordinates

CONTENT TOPOLOGY / ARC NAV
  owns record membership in one or more collections
  owns Previous / Next within those collections
  owns alternate collection membership
  does not independently own the visitor's actual return history

EMBEDDED READER
  realizes the selected document
  reports/intercepts navigation intent at the existing Terrain boundary
  does not mint a second journey state

LOCAL PRESENTATION PREFERENCES
  may alter presentation such as collection-entry zoom depth
  do not become Journey identity, collection identity or URL-route truth

LOCALIZATION
  owns actual language capability and language-surface projection
  does not infer navigation identity or semantic ownership

INSTRUMENTATION
  records the accepted resolution after the rightful owner decides
  may expose/debug the underlying architecture
  does not become a second navigation or behavior engine
~~~

The current Terrain seam therefore resolves through an existing relationship rather than another
navigation system:

~~~text
current Terrain relationship
+ incoming embedded topology control
-> classify relationship

clicked parent == actual current return group
  -> use existing Terrain return/history relationship

clicked parent != actual current return group
  -> real cross-topology traversal

clicked Previous / Next record
  -> record-topology traversal
  -> preserve the appropriate Terrain return relationship
~~~

This directly carries the newest VexSync Origin Walk pressure:

~~~text
navigation owns movement
semantic state remains behind its rightful traceable dependency
payload/argument transport does not become relationship identity
minimum complete preserves the materially necessary why
~~~

It also carries the PR #193 instrumentation boundary:

~~~text
semantic owner decides
-> execution coordinates
-> instrumentation observes accepted fact
~~~

No new event bus, navigation registry, generic preference framework, or browser-side Family clone is
earned by this map.

## Control admission ledger — roles first, canonical names held

Name Ontology also constrains **Controls**. A visible button/link is evidence of an affordance, but its DOM id,
label, or implementation function does not automatically become a canonical Control identity.

Current patient-zero surfaces:

~~~text
Terrain toolbar Back
  implementation evidence:
    #readerBack
    closeEvolutionReader() / browser history
  semantic question:
    return to the actual prior presentation relationship
  current naming disposition:
    UI label/source term = Back
    canonical Control identity = HELD

Arc parent link
  implementation evidence:
    lib/vextreme-index-v2.js renders arcMeta.url under the collection title
  semantic question:
    traverse to the collection parent represented by this Arc membership
  current naming disposition:
    topology relationship is understood
    canonical Control identity = HELD
    must not be renamed Back merely because one current-parent case converges on Back

Arc Previous / Next
  implementation evidence:
    ordered prevSlug / nextSlug projection
    common.nav.prev / common.nav.next presentation strings
  semantic question:
    traverse to predecessor / successor inside one ordered Arc membership
  current naming disposition:
    existing UI terms preserved
    canonical Control identity = HELD

semantic-depth / automatic-entry preference
  implementation evidence:
    Terrain depth rail + collection-entry ratio control
  semantic question:
    adjust local presentation threshold before automatic semantic entry
  current naming disposition:
    presentation preference
    NOT a Journey Control
    NOT an Arc membership Control
~~~

The admission rule is:

~~~text
VISIBLE AFFORDANCE
!= CANONICAL CONTROL IDENTITY

DOM ID / FUNCTION NAME / UI COPY
!= SEMANTIC CONTROL NAME

same rendered consequence in one context
!= same Control

candidate Control name
-> cold-read human question / owner / consequence radius
-> compare with actual relationship
-> mint only if independent addressability is useful
~~~

This prevents the refactor from converting every click target into architecture vocabulary. The current
source can keep ordinary UI labels while the semantic boundary becomes clearer underneath.

~~~text

  Terrain semantic relationship is committed

  Journey entry carries relationship / reason

-> INSTRUMENTATION / UI MAY PROJECT IT
  drawer, debug view, proof, analytics adapter

INSTRUMENTATION
!= second route resolver
!= second Journey state
!= authority to reinterpret the relationship
~~~

Therefore no generic navigation logger, event bus, or telemetry Family is earned by the current seam.
If later lived use benefits from showing more of the architectural 'bones', the smallest candidate is to
project the already-stored Journey `reason` in a human-readable inspection surface rather than creating
a parallel event stream.

Name Ontology applies here too: `logger`, `event`, `debug`, and implementation callback names are not
semantic Family or Control identities. The semantic noun remains the truthful domain object — currently
Terrain Journey — while diagnostic transports remain projections.

## Receive God localization seam — route to the existing owner

The original lived observation also exposed a second seam: **Receive God does not currently have a real
localized language capability**.

Current source facts:

~~~text
pages/receive-god.html
  html lang = en
  data-vex-entry-document = receive-god
  carries fab-read-aloud.js
  does not carry data-i18n identities

tests/86-terrain-entry-pages.test.js
  classifies Receive God / Take a Walk as provider-neutral entry documents
  outside ordinary archive-record discovery
  explicitly rejects retained provider/runtime data-i18n markers

data/index.json
  pageLanguageMap[receive-god] = ABSENT
  slugMap[receive-god] = ABSENT

docs/architecture/06-i18n.md
  element key = canonical localization/UI identity layer
  pageLanguageMap = generated page capability projection
  selected-language authority = existing widgets/fab-lang.js contract
  unmapped surface -> fail closed to EN
~~~

Therefore:

~~~text
NO PAGE LANGUAGE IDENTITY
+ NO TRANSLATION SCOPE / COMPLETE LANG SET
-> NO TRUTHFUL LANGUAGE CAPABILITY

MISSING LANGUAGE ORB
!= forgot to load fab-lang.js

ADDING A LANGUAGE FAB WITHOUT PAGE CAPABILITY
-> false UI promise
~~~

The entry-document contract and the ordinary localized record contract are intentionally different today.
A correct evolution must answer how an ordered entry/group-home document can gain provider-neutral
canonical string identities and page-local language capability **without being reclassified as an archive
record or adopting a duplicate selected-language owner**.

### Name Ontology consequence

Do **not** mint:

~~~text
ReceiveGodLocalizationFamily
EntryDocumentLanguageFamily

~~~

from this observation.

Cold-read, each would imply a new behavioral truth owner where current source already has explicit

That question should be solved in the existing localization vocabulary first. A Family is earned only if
later evidence reveals a distinct independently meaningful behavior question with its own current truth.
