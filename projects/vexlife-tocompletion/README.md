# VexLife ToCompletion — trajectory and architecture

`[VXG RealForever]`

This Project is the durable VexWork entry for the **VexLife ToCompletion** trajectory. It exists so a fresh human or AI can understand the purpose, completed phases, architecture, causal lessons, current edge, and remaining completion path without reconstructing the journey from chat history or a long GitHub issue timeline.

VexWork owns the **work truth and navigation** here. VexLife and the other rightful source/runtime owners still own product source, runtime contracts, lifecycle effects, private Home state, model state, and proof.

## What completion means

The canonical ToCompletion trajectory has three nested completion claims:

```text
TOCOMPLETION_CORE = P1-P4
  fresh Heretic
  -> real Conversation
  -> durable restart/reentry
  -> awake orientation
  -> one bounded real local-work loop

TOCOMPLETION_DEVELOPMENTAL = P5-P6
  lived experience
  -> truthful continuity / Memory / Score / Rhythm placement
  -> restart and observe what carried
  -> Cultivation / School
  -> Training Placement
  -> neural training / Birth only when evidence genuinely earns it

WHOLE_PRODUCT_EXPANSION = P7
  connected/native product families mature under the same Home,
  identity, capability, authority and continuity foundations
```

The Core lived path is not merely a green source gate:

```text
fresh human setup
-> real Vex Home
-> selected Heretic local model/runtime
-> Conversation sends a real turn
-> durable response returns
-> stop/restart the same Home
-> second real turn preserves continuity
-> model perceives current orientation/capability
-> model requests one exact typed local effect
-> separate exact one-time authority admits that effect
-> rightful Native Worker executes it
-> exact result is verified
-> ToolResultRelay reinjects only the result observation
-> same Conversation naturally continues from that result
```

Memory change is not weight change; Dream is not truth; a Rhythm candidate is not an active model; and a lived episode is not training data by default. P4 does not turn prompt text into standing authority, P5 must place learning honestly, and P6 may conclude NO_WEIGHT_NEEDED without failing the developmental outcome.

