# VexLife P0B lineage

`[VXG RealForever]`

VexWork was not invented in an empty repository. Its first real pressure came from VexLife ToCompletion, where a long-running cross-cutting project could no longer depend on prose continuity alone.

## Accepted predecessor sequence

Public VexLife history established:

```text
PR #908  Project Continuity + read-only Board foundation
PR #909  Project Planning + validated transactions
PR #910  source/proof/GitHub reconciliation
PR #911  Purpose Workspace Board/Graph interaction consumer
PR #912  real VexLife ToCompletion Project dogfood
```

That work proved several distinctions worth preserving:

```text
PROJECT != REPOSITORY
WORK_NODE != GITHUB_ISSUE
GITHUB_ISSUE != CANONICAL_WORK_STATE
BOARD_COLUMN != WORKGRAPH_LIFECYCLE
PROJECT_VIEW != EFFECT_AUTHORITY
SPRINT_MEMBERSHIP != WORK_STATE
PR_MERGED != WORK_CLOSED
VALID_WORKGRAPH != RUNTIME_CURRENT_WORKGRAPH
```

## What VexWork extracts

VexWork takes ownership only of the portable work-management questions:

- Workgraph identity, lifecycle and relationships;
- Projects as human outcome groupings;
- Board/Graph/Focus projections;
- repository navigation relations;
- provider relations that remain non-canonical;
- later portable planning/reconciliation/runtime contracts when they are deliberately migrated.

## What remains outside

VexWork does not take ownership of:

- VexLife product semantics or Feature Registry;
- VexLife Home/Companion runtime;
- Vextreme or Android repository culture;
- source mutation authority in another repository;
- model/runtime/training authority;
- GitHub lifecycle authority.

## Licensing / implementation note

VexLife is MPL-2.0. VexWork is Apache-2.0. The initial VexWork source is an independent implementation of the portable semantics and interoperability vocabulary; it does not copy VexLife implementation source into this repository.

## Migration rule

Do not create two live canonical work owners by casually copying runtime state.

A future migration should:

```text
prove VexWork portable contract current
-> provide explicit VexLife compatibility reader/adapter
-> migrate one bounded Project identity
-> compare Board/Graph/Focus meaning
-> choose one canonical runtime writer
-> leave the old source as compatibility/projection or retire it deliberately
```

Until then, VexLife P0B remains accepted predecessor lineage and VexWork is the new portable foundation under construction.
