# VexWork process maps

`[VXG RealForever]`

A VexWork process map exists when a recurring work question should not be rediscovered from chat history, provider habit, or predecessor improvisation.

```text
real repeated / sufficiently general pressure
-> identify the reusable work question
-> separate work-routing meaning from product-specific implementation
-> source-place the smallest rightful process
-> reference target-repository process owners rather than copying them
-> future work reuses the route
```

VexWork owns processes whose meaning is specifically about **entering, relating, grouping, parking, revisiting, or projecting work**.

It does not become the owner of every repository's engineering process.

```text
VEXWORK_PROCESS_MAP != PROCESS_EXECUTOR
PROCESS_REF != EFFECT_AUTHORITY
REFERENCE_TO_ANDROID_FEATURE_PROCESS != OWNERSHIP_OF_ANDROID_FEATURE_PROCESS
```

Current process entries:

- [`FORM-PROJECT.md`](FORM-PROJECT.md) — form one durable Project/outcome grouping without turning formation into implementation authority.
- [`CAPTURE-DISCOVERED-WORK.md`](CAPTURE-DISCOVERED-WORK.md) — preserve adjacent work without widening the active lane.
- [`QUALITY-REVIEW.md`](QUALITY-REVIEW.md) — reusable QA/falsification review contract with exact-target currentness, question matrix, evidence scope, and semantic disposition.

Machine-readable navigation lives in `blueprint/process-registry.json`.
