# VexWork orientation

`[VXG RealForever]`

## Human question

How should a fresh human, hosted assistant, or future local Vex enter Vex work with enough shared understanding to exercise judgment before the foreground work is introduced, without turning orientation into another workflow, checklist, lifecycle, or truth owner?

The answer is deliberately simple:

~~~text
current sources
-> fresh instance reads them
-> instance reflects what it currently understands them to mean together
-> each reflection is questioned in sequence
-> assumptions and their inverse failures become visible
-> foreground work is introduced
-> judgment carries the work
-> consequential decisions reconcile before and after action
~~~

This source preserves the reusable orientation relationship. It does not preserve one predecessor's answers.

~~~text
ORIENTATION != WORKFLOW
ORIENTATION != WORKSTATE
ORIENTATION != PROCESS EXECUTOR
ORIENTATION != EFFECT AUTHORITY
ORIENTATION ANSWER != DURABLE TRUTH
PREDECESSOR CONFIDENCE != SUCCESSOR AUTHORITY
~~~

## Read current sources before reflection

Do not ask the orientation questions into an empty model and do not pre-shape the answers around a foreground task.

First understand the current world far enough to know what the sources are and how they relate.

The reusable entry relationship is:

~~~text
company / lived history
  -> current Vextreme history / terrain surfaces when relevant

current Local Vex Operations
  -> current host/project entry, posture, continuity, completion,
     source/host boundaries, and human boundary

VexWork repository
  -> AGENTS.md
  -> docs/CULTURE.md
  -> docs/foundation/INDEX.md
  -> implicated VexWork foundations

VexRelay relationship
  -> docs/foundation/OPERATING-PROFILES.md explains the VexWork boundary
  -> bind the current VexRelay implementation/contract only when a concrete
     effect actually implicates Relay

target repository
  -> its own current front door / culture / source when source work descends there
~~~

Do not copy those owners into this document. This orientation surface exists so a fresh reader can compile their current meaning together.

## The orientation walk

The reflections are sequential.

Do not answer all of them at once. The answer to each reflection becomes part of the material examined by the next one.

### Reflection 1 — current understanding before work

After reading the current sources, answer:

> Given the current sources you just read, what are your current assumptions before the foreground work is introduced? Explain what you understand those sources to mean together, not only what each source says separately. Distinguish accepted source from your interpretation where that distinction matters.

The purpose is not confession or ceremony. It is to make the instance's compiled current understanding visible before a particular task gives it something to defend.

### Reflection 2 — consequences of the understanding you just expressed

Then examine the whole prior answer:

> Looking at your own answer, which assumptions inside it could create delay, process that generates more process, or work that creates future work while appearing to progress? Also examine the inverse: where could pressure to move, simplify, or finish create premature closure, hidden debt, loss of required distinctions, or a false completion claim?

Do not select only the failure mode that sounds most responsible.

The point is to see how an apparently good principle can become an obstruction, and how its opposite can fail too.

### Reflection 3 — perceive both sides of the whole property

Then take the consequential assumptions through their inverses:

> What does the whole property look like when neither pole is treated as the answer? Return both sides to Holy Father God rather than attaching to one as the corrective ideology. From that fuller view, restate the orientation around the human intention, current evidence, truthful action, and completion.

Examples of dualities may emerge, but the instance is not given a mandatory taxonomy in advance. The current understanding should reveal which dualities actually matter.

Examples already pressure-tested in prior work include:

~~~text
delay <-> haste
over-analysis <-> under-analysis
process accretion <-> process bypass
perfectionism <-> premature closure
excessive decomposition <-> false unification
proof obsession <-> confidence substitution
recovery avoidance <-> replay compulsion
ownership avoidance <-> inappropriate ownership
stopping too early <-> endless progression
~~~

These examples are evidence that both poles can distort judgment. They are not a checklist that limits what a fresh instance may perceive.

## Only then introduce the foreground work

The foreground Work should be introduced after the source-grounded orientation.

~~~text
read current world
-> reflect current understanding
-> challenge consequences
-> perceive inverses / whole property
-> introduce current Work
-> descend only as the Work now requires
~~~

This order matters.

If the specific Work is revealed first, a fresh instance may unconsciously bend the orientation toward proving a task-specific theory. If the reflection happens before current sources are read, the instance mostly audits generic model habits rather than its actual understanding of Vex.

## Judgment becomes the flow

The intent is not "follow the onboarding process."

The refined sources already own the truths and boundaries. Orientation helps a fresh instance perceive how those truths compose. Once the foreground work is admitted, judgment carries the trajectory.

~~~text
source defines what is current
intention defines why the work exists
evidence constrains what may be claimed
judgment selects the next truthful action
completion retires the admitted causal obligation
~~~

Artifacts, PRs, branches, tests, Relay packages, receipts, reviews, and handoffs are machinery or evidence. They are not progress merely because they exist.

## Before and after a consequential decision

Do not replay the full orientation walk before every edit.

Instead revisit its gist when a decision can materially change source, architecture, scope, authority, product behavior, or the completion claim.

Before acting, ask enough to know:

~~~text
What do I currently understand the human intention and causal edge to be?

What assumption am I relying on to make this move?

Is the failure I am correcting observed,
contract-required,
or only hypothetical?

What valid property would my proposed correction weaken,
remove,
or make harder if it succeeds?

What is the inverse failure if I overcorrect in the other direction?

Do current source and evidence give me enough to act truthfully now?
~~~

Then act when the answer is sufficient.

After observing the result, reconcile:

~~~text
What actually happened?

Did reality support or falsify the assumption behind the move?

Did this retire causal obligation,
repair an obligation we created ourselves,
only produce evidence,
or create new debt?

Did I leave a mistake, false premise, or stale interpretation behind
that would become somebody else's future work if I simply continue?

What must change in current understanding before the next move?
~~~

No extra receipt or document is required merely to prove that reflection happened. Durable source changes only when durable truth actually changed.

## Continuation is the default

A checkpoint or completed step does not by itself end the trajectory.

~~~text
reconcile what happened
-> name the next unconsumed causal edge
-> continue
~~~

Stop only when the admitted outcome is complete or a genuine human, authority, capability, or transfer boundary holds the dependent effect.

~~~text
CHECKPOINT != STOP CONDITION
STEP COMPLETE != TRAJECTORY COMPLETE
~~~

## Bounded recursion

Orientation may itself become foreground Work.

~~~text
CURRENT SOURCE
-> ORIENT
-> WORK

if WORK changes orientation:
  review / change it as Work
  -> prove / reconcile
  -> updated current source
~~~

Do not create nested orientation gates merely because onboarding itself is being reviewed.

## Fresh-instance takeover

A fresh conversation is not a fresh trajectory.

When execution reaches a real threshold where another instance must take over, do not replace the Work with a giant successor narrative and do not require the successor to inherit the predecessor's cognitive conclusions.

The successor entry is:

~~~text
1. fresh instance reads the current sources;
2. fresh instance completes the orientation walk;
3. only then reintroduce the already-existing work plan;
4. state the exact current position in that plan;
5. state completed valid effects and the exact held/missing predicate;
6. provide the current evidence needed to verify that position;
7. let the newly oriented instance decide what additional source/evidence
   must be gathered before adding more code.
~~~

The plan is continuity, not authority.

A newly oriented instance may preserve, refine, simplify, or replace part of the predecessor's plan when current source/evidence earns that judgment. It should not restart completed valid work merely because the conversation is fresh.

A useful takeover packet is therefore small:

~~~text
ORIGINAL HUMAN OUTCOME
EXISTING WORK PLAN
CURRENT PLAN POSITION
COMPLETED VALID EFFECTS
HELD / MISSING PREDICATE
CURRENT EVIDENCE / SOURCE COORDINATES
~~~

Not required:

~~~text
predecessor private reasoning
full chat replay
all historical provider comments
every failed attempt
the predecessor's orientation answers
~~~

## Static shared surface

The public read-only representation is `orientation.html`.

It is deliberately readable by humans and agents from the same surface and links back to current source rather than becoming a second architecture manual.

The page may explain relationships and preserve the sequential reflections. It must not:

- mutate Workgraph truth;
- persist orientation answers as canonical state;
- grant source/effect authority;
- freeze a private/current VexRelay contract into VexWork;
- replace target-repository culture;
- turn the reflection walk into a mandatory approval gate.

## Completion pressure

This orientation foundation is useful when a genuinely fresh entrant can:

~~~text
read current sources
-> compile their meaning
-> surface material assumptions before work
-> perceive inverse failure modes
-> receive current Work + existing plan + exact plan position
-> gather only the additional context the Work actually needs
-> act
-> reconcile consequential results
-> continue without predecessor-chat archaeology
~~~

If that lived entry still depends on Victor manually reconstructing what the predecessor meant, the onboarding outcome remains incomplete.
